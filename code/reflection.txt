Unlike Assignment 02, where data lineage was implicit, this assignment gave us the experience of how important it is through the copy-add-return function, which states that the function must perform: out = frame.copy(), add one column, and return out. Copying is essential because in my first attempt I had the impression that a step could mutate the frame, but the lineage test makes sure that is not the case, not just the output. Graining was an essential concept in Assignment 04, since there were different grains in each data frame. The roster has a granularity where one row represents one person, but the timesheet has a granularity of one row representing a person-who-worked-that-week. This meant that merge_employees should have merged the two data frames using a left join on employee_id as the key, which keeps all the rows in the timesheet dataframe, including unmatched ones that get NaN for the roster columns.

It became much easier to understand the two apply patterns after comparing them. The Series.apply() method in clean.py runs one function, such as parse_hours or clean_currency, row by row along a single column. add_gross_pay() in compute.py required a different approach using DataFrame.apply(axis=1) and a lambda expression because it relied on two values from the same row, hours_worked and hourly_rate_usd. Although I understand how they differ now, I would still like to practice until I know immediately which one to use without stopping to think.

I even learned something about debugging that was real but not related to pandas. At one point, pasting into the terminal broke compute.py by combining some of my old TODO placeholders with the new code. As a result, the functions began silently returning None rather than producing a noticeable error, and I did not catch it until I started seeing failures across three separate test files. The problem was solved by using a heredoc to rewrite the file directly from the terminal. It taught me that I should verify a file's actual saved content, such as by running cat on it, instead of assuming a paste worked.

Developing payroll_export also taught me why renaming columns on the pipeline's own frame would be bad practice. Building a whole new DataFrame from the filtered rows of payroll[payroll["pay_type"] != "unmatched"] let me shape the output for the provider without touching the pipeline table's lineage.
